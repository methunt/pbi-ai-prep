- (decision) PARADIGM: hexagonal core over a source-anchored patch writer. Pure domain core (model objects, object graph, change journal, fidelity rules) with adapters (tmdl/lsdl/pbir readers, fs, ai). Write path patches original bytes by span, never re-serializes from an AST. Binds whole product; prevents a re-serializing writer that loses bytes and an un-tested write path.
- (decision) AD-1: Hexagonal dependency rule. src/domain imports nothing from React, DOM, or File System Access API; adapters and the store import the domain; never the reverse. Binds all FRs. Prevents format/fs logic leaking into the domain and making fidelity testable only in a live browser.
- (decision) AD-2: Object identity is lineageTag (stable under rename) with a deterministic surrogate (file#byte-span) for objects lacking one. Selection, pending-change journal, and graph nodes all key on one id. Binds FR-12, FR-30, FR-14, FR-17. Prevents three identity schemes (selection by name, journal by path, graph by name) diverging; a rename is a recorded change, never a re-key.
- (decision) AD-3: Source-anchored byte patching, never re-serialize. Parse yields per-file {path, originalText, spans}; each model object records the byte range of its declaration and doc comment. Writes apply span patches to a pristine copy of originalText in descending byte order. Binds FR-22, FR-23, FR-33. Prevents loss of ordinal, lineageTag, contentType: json, annotations, formatting, and any byte drift on an edit-free save. A writer that re-serializes is a bug; the patch engine is the only writer.
- (decision) AD-4: Change journal, not mutated model. EditSession is an ordered journal of per-field records {objectId, field, old, new, file, context}; the parsed model stays pristine; all surfaces read model XOR journal; discard removes a record; nothing writes until Save. Binds FR-14, FR-30, FR-31, FR-33. Prevents in-place mutation losing old value for review/discard and the grid/lineage/pending-modal reading divergent state. No UI mutates a ModelObject directly.
- (decision) AD-5: Atomic, permission-aware, conflict-checked write. Save path: group journal by file; for each file verify on-disk content still equals the parse snapshot (FR-25: block + reload-or-overwrite naming the file on mismatch); apply patches descending; write via createWritable (atomic replace); report written files. Revoked permission mid-save: report files already written, retain the journal, offer a user-gesture retry (FR-24). Binds FR-22, FR-24, FR-25. Prevents partial writes, silent overwrite of external edits, and a builder bypassing the conflict check by always overwriting.
- (decision) AD-6: One ObjectGraph, two feeders. A single pure dependency engine over fixed edge kinds (visual->obj, measure->obj, calcObj->source, calcItem->DAX, fieldParam->NAMEOF, function->body, table->table rel; visual->visual excluded). Model edges (TMDL/DAX) build eagerly or on demand and are memoized; report edges overlay later; Used count, lineage canvas, and delete blast-radius all read this one graph. Binds FR-9, FR-20, FR-33, FR-37. Prevents the grid Used pill and canvas side panel disagreeing on counts. Add an edge kind, never a second graph.
- (decision) AD-7: Eager model-object parse; lazy LSDL/report/lineage; heavy parses on a worker. On folder open parse the definition tree into model objects within the 5s budget; LSDL, report layer, and report-edge lineage parse lazily on first need (Prep for AI tabs, Lineage tab, usage columns). Heavy parses run in a Web Worker so the main thread never blocks >50ms (FR-8). Binds FR-5, FR-7, FR-8, FR-35. Prevents eager LSDL parse blowing the 5s budget at 2000 objects and a builder making the grid depend on report data.
- (decision) AD-8: Report-layer and LSDL writes exist for exactly one mechanical purpose: rename propagation of field bindings and the LSDL entity binding key (FR-12). No other report-layer or LSDL write exists. Binds FR-12, FR-6, FR-17 + PRD §6.1. Prevents non-rename writes damaging report visuals and the LSDL entity binding silently drifting from a renamed object.
- (decision) AD-9: Encoding/layout are not optional. UTF-8 without BOM; preserve each file's original line endings (CRLF preserved); TMDL tab indentation; /// doc comments (never //); LSDL state enum values written verbatim (User, Generated, Suggested, Deleted, Authored); doc comments at declaration indentation. - (decision) AD-10: Single Zustand store owns all cross-surface state: loaded project (parse result + spans + original texts), the change journal, selection (keyed by lineageTag, survives filter/page/search/tab nav), filter/sort/pagination, per-layer parse state, KPI counts.
